# 여행 검토용 읽기 가이드

## 읽을 범위

기본 순서: overview.md → itinerary.md → bookings.md. 식사 검토 시 food.md를 추가로 읽는다. 날짜별 세부 시간은 itinerary.md에 모두 있으므로 처음부터 앱 코드를 읽을 필요가 없다.

- 일정·식사 생성 문서: scripts/export-trip-docs.mjs로 lib/trip.ts와 lib/restaurants.ts에서 생성.
- 사용자 조건·예약 보완: overview.md, bookings.md. 새로 확인한 사실은 확인일·근거와 함께 갱신.
- 필요할 때만: lib/map-points.ts(위치), lib/trip.ts(공식 링크·원본), lib/weather.ts(고정 예보).
- 제외: app/, public/, components.json, node_modules/, vendor/, build/, drizzle/, lockfile, 설정 파일. 코딩 요청이 있을 때만 읽는다.
- 보험 문서는 ../reference/axa_policy.pdf. 보험 검토 요청이 없으면 읽지 않는다.

## 정확성

- GitHub는 기본 계획의 스냅샷이다. 웹사이트 D1/R2 운영 데이터의 이후 편집·투표·지출·예약 기록을 포함하지 않는다.
- 문서·코드·사용자 최신 증빙이 충돌하면 차이를 명시하고 날짜·근거를 확인한다. 예약 상태를 자동으로 확정하지 않는다.
- 계획 확정, 예약·결제 완료, 후보, 확인 필요를 구분한다.
- 식당·어트랙션·공연·영업시간·가격·날씨는 공식 출처로 최신 확인한다. 과거 문서의 시간표를 실제 공연 시각으로 인용하지 않는다.
- lib/weather.ts는 2026-10-29 조회한 고정 예보다. 현재 예보나 기후 평균으로 취급하지 않는다.
- 사람·주말 조건을 유지하고, 대안 후보를 전부 필수 일정으로 더하지 않는다.

## 다른 AI에 전달할 프롬프트

GitHub https://github.com/Jayk-resonance/Los-Angeles-trip 의 최신 기본 브랜치를 참고해 LA 여행 일정을 검토해줘. 코드 리뷰가 아니라 실제 동선·시간·피로도·비용·예약 준비 검토가 목적이야. 파일이나 사이트는 수정하지 마.

읽기 순서:
1. README.md와 docs/trip/review-guide.md
2. docs/trip/overview.md
3. docs/trip/itinerary.md
4. docs/trip/bookings.md
5. 식사 검토 시 docs/trip/food.md

처음에는 이 문서만 읽고, 위치·공식 링크 등의 추가 근거가 필요할 때만 가이드에서 지정한 원본 파일을 열어줘. 이미지·글꼴·lockfile·앱 구현·빌드 파일·보험 PDF는 읽지 않아도 돼. 저장소 접근이 안 되면 읽은 척하지 말고 필요한 문서명을 요청해줘.

예약 완료와 방문 계획·후보를 구분하고, Alamo 예약 사실은 bookings.md를 참고해. 저장소는 웹사이트에서 직접 편집한 최신 운영 데이터와 다를 수 있어. 충돌이 있으면 단정하지 말고 확인할 내용을 명시해줘.

영업시간·휴무·공연·가격·날씨는 공식 최신 정보로 확인하고, 이동에는 주차·도보·대기·식사 여유를 포함해줘. 10/31–11/1은 재혁과 조슈아트리, 11/1 쇼핑 제외, 평일 낮은 제우·승빈, 저녁은 재혁 합류라는 조건을 지켜줘. 날짜·시각은 LA 현지 기준으로 해석하고 이미 지난 날보다 남은 일정을 우선 검토해줘.

답변은 현재 전체 일정 요약 → 반드시 조정할 문제/선택적 개선 → 최소 변경 일정과 기존안 비교표 → 예약·추가 확인 목록 순서로 작성해줘. 바꿀 때는 줄이는 일정과 이유도 설명해줘. 문제가 없는 일정은 유지해줘.
